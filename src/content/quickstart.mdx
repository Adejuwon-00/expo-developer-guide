Get **Task starter** running on your phone, then mark a task complete. You
won't need to write code or configure a native build for this first run.

## Before you begin

- Install [Git](https://git-scm.com/downloads), which copies the repository to
  your computer, and [Node.js](https://nodejs.org/en/download) with npm, its
  package manager. The checked environment is **Node.js 22.16.0 and npm 10.9.2**;
  the example's `package.json` lists other accepted Node.js versions.
- Install [Expo Go](https://expo.dev/go) on your phone with **Expo SDK 58**
  support. The SDK is the release family of Expo packages used by this app;
  the client needs to support that family to run the code.
- For an iPhone, have an Expo account ready. The CLI and Expo Go must use the
  same account, following [Expo's device instructions](https://docs.expo.dev/get-started/start-developing/).
- Connect the computer and phone to the same Wi-Fi network.

You don't need a Thally account, Xcode, or Android Studio for this workflow.
Use a terminal for the commands below. If PowerShell blocks `npm.ps1`, follow
[the Windows workaround](#powershell-blocks-npm-ps1) rather than changing your
system policy.

## 1. Copy the project and install its packages

From the directory where you keep projects, run:

```sh
git clone https://github.com/Adejuwon-00/expo-developer-guide.git
cd expo-developer-guide/examples/expo-task-starter
npm ci
```

`git clone` downloads the repository. `cd` moves into the example directory.
`npm ci` installs the package versions recorded in its lockfile. Wait for it
to finish before continuing.

**Check:** the install should finish without an npm error. You should now be
in `examples/expo-task-starter`, beside its `App.tsx` and `package.json`.
Warnings can appear without the install failing; see
[installation troubleshooting](#installation-fails-or-reports-warnings) if needed.

This example has its own dependencies. Installing packages in the repository
root sets up the Thally documentation site instead of the mobile app.

## 2. Sign in for an iPhone

**Using Android? Skip to [Start Expo](#3-start-expo).**

From the same example directory, run:

```sh
npx expo login
```

`npx` runs the CLI supplied by the installed Expo package. Complete its
sign-in flow, then open Expo Go on your iPhone and sign in through the account
icon using the same Expo account.

**Check:** both sign-in flows should complete using the same account. If the
phone later reports an account mismatch, use [the recovery steps](#expo-go-asks-you-to-sign-in-or-reports-an-account-mismatch).

## 3. Start Expo

Still in `examples/expo-task-starter`, run:

```sh
npm start
```

This starts Metro, the development server that prepares and serves the app's
code. Leave this terminal open while you use the app.

**Check:** the terminal should show a server address and QR code. Use
`npm start` in this directory; `npm run dev` runs the documentation site
from the repository root.

## 4. Open the project on your phone

### iPhone

Open the Camera app, scan the terminal's QR code, and follow the link to
Expo Go. Allow local-network access if iOS asks.

### Android

Open Expo Go and use its QR scanner to scan the terminal code. These steps
follow [Expo's supported device workflow](https://docs.expo.dev/get-started/start-developing/).

**Check:** you should see **Task starter** and this list:

| Task | Initial status |
| --- | --- |
| Run the app on your phone | Not completed |
| Mark a task complete | Not completed |
| Explore the starter code | Completed |

If the project doesn't open, start with [connection troubleshooting](#expo-go-can-t-reach-the-server).

## 5. Change a task and confirm the result

Tap **Run the app on your phone**. Its checkbox and text treatment should
change, and its status should become **Completed**. Tap it again to restore
**Not completed**. The other two rows should keep their status.

Press `r` in the Metro terminal for a full reload. The initial states in the
table should return: this example doesn't save tasks. Returning from the
background or Fast Refresh, which updates code while you edit, may keep state.
Press `Ctrl+C` when you want to stop the server.

## If something gets stuck

### npm can't find the start script

Check your current directory. You need
`examples/expo-task-starter/package.json`, whose `start` script is `expo start`.
If your terminal is at the repository root, run
`cd examples/expo-task-starter` before retrying `npm start`.

### PowerShell blocks npm.ps1

If PowerShell says scripts are disabled, use `npm.cmd ci` and `npm.cmd start`
in place of `npm ci` and `npm start`. For login, use `npx.cmd expo login`.
These run the same installed tools without changing the system execution policy.

### Expo Go asks you to sign in or reports an account mismatch

On a physical iPhone, use the same Expo account in the CLI and Expo Go. Run
`npx expo login` from the example directory, sign in through Expo Go's account
icon, then press **Try Again** on the account error. Follow the specific error
message if it identifies which side needs signing in. See
[Expo's recovery instructions](https://docs.expo.dev/get-started/start-developing/#having-problems).

### Expo Go can't reach the server

Confirm that the Metro terminal is still running and that both devices use
the same Wi-Fi network. VPNs and guest-network isolation can block local
connections. On Windows, allow Node.js through the firewall for your trusted
**private** network when prompted. On iPhone, check Expo Go's local-network
permission in Settings. Reopen the QR link after correcting the connection.
Don't disable your firewall globally.

### Expo Go reports an incompatible SDK

Check SDK 58 support on [Expo Go's compatibility page](https://expo.dev/go).
The example locks Expo 58.0.26, React 19.3.0, and React Native 0.88.1. The
client must support that SDK. On a physical iPhone, the App Store provides
the current Expo Go version; older versions aren't generally installable
through that workflow. Keep the lockfile intact rather than changing package
versions to guess at a fix.

### Installation fails or reports warnings

If npm reports an error, inspect it before proceeding. For a registry
connection failure, restore the connection and retry `npm ci` from the example
directory. Keep the lockfile.

Advisory and deprecation warnings can appear after a successful install. The
[validation notes](https://github.com/Adejuwon-00/expo-developer-guide/blob/main/assessment/phase-2-validation.md)
record the known findings. Don't use `npm audit fix --force`: it can replace
the compatible Expo and test-tooling versions.
