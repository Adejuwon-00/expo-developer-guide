Build a small mobile app from code you can read and change. You'll run a task
list on your phone, learn how its screen responds to a press, and add All,
Active, and Completed filters with behavior tests.

You need basic JavaScript familiarity: functions, objects, and arrays. You
don't need previous Expo or React Native experience. If React or TypeScript
is new to you, the lessons explain the parts used here as you encounter them.
If you already use React, you'll recognize the same components and state.

[Start by running the app on your phone](/quickstart). The rest of this page
explains what you'll be running; you can return to it after the first launch.

## React describes the screen; React Native puts it on your phone

A React **component** is a function that describes part of an interface. In
this starter, the `App` component describes the whole screen. React Native
provides components such as `View` for layout, `Text` for text, and `Pressable`
for something you can tap. They render native platform views rather than HTML
inside a browser.

Here is the title from the starter:

```tsx
<Text accessibilityRole="header" style={styles.heading}>
  Task starter
</Text>
```

The tag-like syntax is **JSX**, used to describe the interface in JavaScript.
The attributes are **props**: inputs to a component. Here, `style` supplies
formatting and `accessibilityRole` identifies the text as a heading. Curly
braces insert a JavaScript value, such as `styles.heading`, into JSX.

You don't need to write this screen from scratch. The working version is in
[`examples/expo-task-starter/App.tsx`](https://github.com/Adejuwon-00/expo-developer-guide/blob/main/examples/expo-task-starter/App.tsx).

## Expo gets that code onto a device

Expo provides a framework and tools for building React Native apps. You'll
start its development server on your computer and open the project in
**Expo Go**, an app installed on your phone. The server prepares your code;
Expo Go runs it using the native capabilities already included in that app.

That is enough for this example. You don't need Xcode or Android Studio to
run it through Expo Go. Apps needing custom native code use a development
build instead; that workflow is outside this guide.

## State connects a press to a changed screen

The starter has three task objects. Each has an `id`, a `title`, and a
`completed` value. **State** is data React remembers between renders. A render
is React calling your component to work out what the interface should show.

The app keeps its task array in state:

```tsx
const [tasks, setTasks] = useState<Task[]>(initialTasks);
```

`tasks` is the current array. `setTasks` is the function used to update it;
React then renders the new result. `initialTasks` supplies the starting data.
The TypeScript annotation `Task[]` means an array of task objects. TypeScript
checks the shape of those objects while you work; it doesn't save them.

When you press a row, the app creates an updated array instead of changing the
old objects in place. React uses that new state to show the checkbox and
status text. There is no backend or saved storage: a full reload restores the
sample tasks.

For more React background, see [components](https://react.dev/learn/your-first-component)
and [state](https://react.dev/learn/state-a-components-memory). You can follow
the quickstart without reading those references first.

## What to notice on the phone

- **A whole row responds to a press.** React Native uses `onPress` for this
  interaction. You don't have to aim for the small checkbox.
- **Text and rows can grow.** Styles are JavaScript objects passed through
  props, rather than browser CSS. The starter leaves room for wrapping and
  larger system text.
- **The interface exposes more than color.** Task rows have checkbox labels
  and checked states for screen readers, plus visible status text.
- **System controls take space.** The starter uses safe-area insets to keep
  content clear of a notch, status bar, or home indicator. You'll still need
  to check layout and accessibility on your own device.
