## 1. Add filter controls

### Change

Immediately before `const initialTasks: Task[] = [` in `App.tsx`, add:

```tsx
type Filter = 'all' | 'active' | 'completed';

const filters: { value: Filter; label: string }[] = [
  { value: 'all', label: 'All' },
  { value: 'active', label: 'Active' },
  { value: 'completed', label: 'Completed' },
];
```

Inside `App`, replace the existing `tasks` state declaration with these two declarations:

```tsx
const [tasks, setTasks] = useState<Task[]>(initialTasks);
const [filter, setFilter] = useState<Filter>('all');
```

In `FlatList`, replace the entire `ListHeaderComponent={...}` prop with the following. The existing title and description stay inside the header, followed by the controls:

```tsx
ListHeaderComponent={
  <View style={styles.header}>
    <Text accessibilityRole="header" style={styles.heading}>Task starter</Text>
    <Text style={styles.description}>
      Tap a task to mark it complete. Tap again to bring it back.
    </Text>
    <View style={styles.filters}>
      {filters.map((option) => (
        <Pressable
          key={option.value}
          accessibilityRole="button"
          accessibilityLabel={option.label}
          accessibilityState={{ selected: filter === option.value }}
          onPress={() => setFilter(option.value)}
          style={({ pressed }) => [
            styles.filterButton,
            filter === option.value && styles.selectedFilter,
            pressed && styles.pressedFilter,
          ]}
        >
          <Text
            style={[
              styles.filterLabel,
              filter === option.value && styles.selectedFilterLabel,
            ]}
          >
            {option.label}
          </Text>
        </Pressable>
      ))}
    </View>
  </View>
}
```

In `StyleSheet.create`, replace the existing `header` entry with the following entries. Keep the rest of the stylesheet:

```tsx
header: { marginBottom: 20, gap: 12 },
filters: { flexDirection: 'row', flexWrap: 'wrap', gap: 8 },
filterButton: {
  minHeight: 48,
  minWidth: 48,
  justifyContent: 'center',
  alignItems: 'center',
  paddingHorizontal: 16,
  paddingVertical: 12,
  borderWidth: 2,
  borderColor: '#CBD3D8',
  borderRadius: 10,
  backgroundColor: '#FFFFFF',
},
selectedFilter: { borderColor: '#246247', backgroundColor: '#EDF5F1' },
pressedFilter: { opacity: 0.75 },
filterLabel: { fontSize: 16, color: '#172126' },
selectedFilterLabel: { fontWeight: '700' },
```

### Why

The `Filter` union limits the choice to three strings; `filter` stores the current choice, initially `'all'`. The controls use the existing imports and expose button labels and selected states to accessibility services.

A heavier label supplements the selected border and background, so the choice is not shown by color alone. Controls wrap and grow with larger text, with minimum 48-unit touch targets rather than fixed heights.

### Check

Reload: **All** starts selected. Press **Active** and **Completed**; selection should move, but **all three tasks stay visible**. Filtering comes next. Run the validation routine: the original **four tests** should pass.

If controls are missing, check that you replaced the header prop, not the whole list. For missing styles, compare the names and check that their entries are inside `StyleSheet.create`.

## 2. Show matching tasks

### Change

Replace the `filter` state declaration with this declaration and calculation, leaving `tasks` above it and `toggleTask` below it:

```tsx
const [filter, setFilter] = useState<Filter>('all');

const visibleTasks = tasks.filter((task) => {
  if (filter === 'active') return !task.completed;
  if (filter === 'completed') return task.completed;
  return true;
});
```

In `FlatList`, change only its `data` prop. Before:

```tsx
data={tasks}
```

After:

```tsx
data={visibleTasks}
```

### Why

`visibleTasks` is derived from the full task array and current choice on each render. Active keeps unfinished tasks; Completed keeps finished tasks; All keeps everything. There is no second array in state to synchronize and no effect or memoization needed for three tasks.

Leave `toggleTask`, `keyExtractor`, and `renderItem` unchanged. Updating only the visible array would lose hidden tasks. The new derived array also lets `FlatList` receive the changed data without adding `extraData`.

### Check

Reload, then select each filter:

| Filter | Expected initial tasks |
| --- | --- |
| All | All three tasks |
| Active | Run the app on your phone; Mark a task complete |
| Completed | Explore the starter code |

Complete **Run the app on your phone** while viewing Active. It should disappear there and appear checked under Completed and All. Reopen it from Completed: it leaves that view and returns to Active. Filtering changes what you see; toggling changes completion state.

Run the validation routine: **four tests** should pass. If every filter still shows three tasks, check `data={visibleTasks}`. If the initial view has fewer, check that `filter` starts as `'all'`.

## 3. Handle empty results

### Change

Immediately before `function toggleTask(id: string) {`, add:

```tsx
const emptyMessage =
  filter === 'active'
    ? 'No active tasks. Everything is complete.'
    : filter === 'completed'
      ? 'No completed tasks yet.'
      : 'No tasks to show.';
```

In `FlatList`, replace the consecutive `data={visibleTasks}` and `keyExtractor` props with:

```tsx
data={visibleTasks}
ListEmptyComponent={
  <Text style={styles.emptyMessage}>{emptyMessage}</Text>
}
keyExtractor={(task) => task.id}
```

In `StyleSheet.create`, replace the `selectedFilterLabel` entry with:

```tsx
selectedFilterLabel: { fontWeight: '700' },
emptyMessage: { fontSize: 17, lineHeight: 26, color: '#46545C', paddingVertical: 20 },
```

### Why

`ListEmptyComponent` explains why no rows match instead of leaving a blank list. Its message follows the selected filter. The All fallback is defensive: this starter has no delete action. The controls stay in the list header, available when no rows match and inside the scrolling content when text grows.

### Check

**No active tasks:** Reload, select Active, and complete **Run the app on your phone** and **Mark a task complete**. Expect **No active tasks. Everything is complete.** Return to All: all three tasks remain and are complete.

**No completed tasks:** Reload to restore the initial state, select Completed, and reopen **Explore the starter code**. Expect **No completed tasks yet.** Return to All: all three remain and are incomplete.

Run the validation routine: **four tests** should still pass. If the message is missing, check the `ListEmptyComponent` prop and its style name. You should still be able to change filters from either empty view.

## 4. Test the behavior

Jest and React Native Testing Library are already configured. Keep the original four starter tests. Add the following tests beside them; no package installation is needed.

### Start with the selected state

Create `__tests__/Filtering.test.tsx` with these complete contents:

```tsx
import { render, screen } from '@testing-library/react-native';
import App from '../App';

test('starts on All and exposes the selected filter', async () => {
  await render(<App />);
  expect(screen.getAllByRole('checkbox')).toHaveLength(3);
  expect(screen.getByRole('button', { name: 'All', selected: true })).toBeOnTheScreen();
  expect(screen.getByRole('button', { name: 'Active', selected: false })).toBeOnTheScreen();
  expect(screen.getByRole('button', { name: 'Completed', selected: false })).toBeOnTheScreen();
});
```

`render` creates the test screen; `screen` finds its controls. The role, label, and `selected` queries check the accessibility state, not just visible text. Run `npm test`: expect **two suites and five passing tests**. If it fails, check the initial filter and `accessibilityState.selected`.

### Check transitions and empty views

From the same [reference test file](/references/task-filtering/Filtering.test.tsx.txt), append the last two complete `test(...)` blocks, including their closing `});` lines:
